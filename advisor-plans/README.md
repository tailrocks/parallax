### Verified-fact base (2026-07-10, for future re-audits)

- LIKE body search vs `matches_term` measured live (engine 1.1.0, 500k logs):
  114 ms / 1.3 GiB full scan vs 25 ms / 91.7 MiB pruned. FULLTEXT index is
  never used by LIKE (upstream applier has no Like arm).
- `opentelemetry_logs.body` gets a FULLTEXT (bloom) index by default on
  engine ≥1.1 — Parallax's ALTER deviation is dead code.
- `x-greptime-hints` (ttl/append_mode) apply ONLY at auto-create; existing
  tables silently ignore them → retention config edits never propagate.
- `x-greptime-log-extract-keys` creates missing columns as TAGs (PRIMARY KEY
  members) — first-batch race can make `observed_ts_nanos` a per-row-unique
  PK component.
- OTLP-over-gRPC was removed upstream (PR #5605): Parallax's HTTP forward is
  the only native path (correct by necessity, keep).
- GreptimeDB OTLP endpoint accepts gzip request bodies; Parallax's own
  OTLP/HTTP receiver does NOT (spec violation, silent exporter data loss).
- HTTP `/v1/sql` supports `format=arrow` (+zstd); MySQL/PG wires cache
  prepared-statement plans per session; HTTP re-plans every call; no server
  read API over gRPC is documented.
- `information_schema` lookups are in-memory (~9 ms / 360 tables live) — the
  info-schema round-trips are latency, not scan cost.
- FAQ ingest ranking: text SQL INSERT = 1×, gRPC row SDK ≈ 16×, bulk ≈ 37×.
- `greptime standalone start` has no `--memory-limit`; tuning only via
  `-c`/env; auto-created trace table defaults to 16 trace_id partitions
  (`trace_table_partitions` hint overrides).
- `ensure_binary` returns any existing managed binary — version pin bumps
  never upgrade (live instance ran 1.1.0 against a 1.1.2 pin).

- Recharts/Motion in the shell chunk; Motion used only by the theme switcher —

- `self_telemetry` export filter does not silence `parallax_storage` — if a

## Findings considered and rejected (022-034 audit)

- **Split the 2181-line `crates/parallax-api/src/lib.rs`**: real tech debt, but
  a pure module re-org is not worth a standalone plan now — fold it in
  opportunistically when a feature plan (028-032) adds a resolver.

  but Juniper has no built-in dataloader and the fix is entangled with a

  but pre-existing and orthogonal to the brief; candidate for its own perf
  plan.

  explicitly someday, not plan-worthy now.
- **`Worker.seen_runs` grows unbounded**: slow leak on very long-lived
  servers; low severity, deferred.
- **Persisted occurrence idempotency for late span/log echoes**: valuable but
  schema-changing; 026 lands bounded in-batch dedup and defers a durable seen
  `(trace_id, span_id, fingerprint)` table.
- **`metric_point_count` stubbed to 0 / metric trend empty**: a documented V1
  gap, not a regression; deferred.
- **Stringly-typed UI GraphQL client** (no variables/codegen): real DX debt,
  but the manual escaper is safe today and a codegen migration is a large
  independent change; deferred.
- **Causal reconstruction** (typed nodes/edges + strength tiers): confirmed
  research-only, no code exists. Deliberately NOT planned — story (029) +
  evidence gaps (032) + ecosystem (031) deliver the near-term
  causal-navigation value without it.
