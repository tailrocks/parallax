## Findings considered and NOT planned (so nobody re-audits)

- **SSR "now"/hydration drift** (loaders isomorphic, `Date.now()` in
  loader vs component): LOW confidence, needs a hydration-warning check in
  a real SSR render first — investigate note only (see 038's reviewer
  note); no plan.
- **Playground 100% sampling default**: intentional lab repeatability, not
  a defect; only the dedicated 10% scenario is planned (054).
- **`runs`/`observedRuns` lacking server-side time args**: deferred —
  client-side scoping in 038 is correct at lab volume; add API args when
  run volume grows (noted in 038 Maintenance).
- **GraphQL→gRPC gateway (A23) / GraphQL→GraphQL (A24)**: topology
  additions deferred until the base GraphQL family (047) is visible.
- **Catalog-on-Hikari DB scenarios (Java pool metrics)**: deferred
  follow-up of 048 (one moving part at a time).
- **Parallax `frontendSessions` resolver + sessions UI**: deliberately not
  planned — blocked on the data contract 050 produces
  (`docs/frontend-telemetry-contract.md` in the playground repo); spec the
  resolver against it afterward.
- **Seeded/back-dated history window for the demo**: covered adequately by
  037's continuous loadgen; `seed.rs` integration noted there as a
  considered-and-dropped alternative.
- **notifications service stub (no domain spans)**: partially covered by
  036 (extraction) and deferred otherwise (noted in 048).
- **Toast/notification system for the UI**: inline errors are the pattern
  (035); a toaster is a design decision left to a future pass (053 notes
  it).
- **kbd/OpenObserve/Rotel lab path changes**: the fan-out lab flow stays
  untouched; the demo path (037) is additive.

## Verification baseline

Parallax UI (from `ui/`): `bun install`; `bun run typecheck` / `lint` /
`test` / `build` — all must exit 0 (Bun only; never npm/pnpm/yarn).
Parallax Rust (repo root): `rtk cargo build --workspace`,
`rtk cargo clippy --workspace --all-targets` (zero warnings),
`rtk cargo fmt --all`, `rtk cargo nextest run`.
Playground (its repo root): `rtk cargo build`,
`rtk cargo clippy --all-targets -- -D warnings`; Java via each service's
Gradle wrapper; web via `bun run build`;
`docker compose -f deploy/docker-compose.yml config` for compose changes.
Manual checks need `parallax serve` + the playground
(`OTEL_EXPORTER_OTLP_ENDPOINT` already matches ports 4317/4318).
Git: work on `main` (BRANCHING.md), Conventional Commits (COMMITS.md),
`git commit -s`, exactly one `Co-authored-by: Claude <noreply@anthropic.com>`
trailer per agent commit, push when done. Playground-target plans commit in
the playground repo but update their status row here.
